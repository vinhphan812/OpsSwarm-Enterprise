# OpsSwarm Enterprise Branding

## Primary brand emblem

The canonical OpsSwarm Enterprise emblem is the selected transparent shield-based visual identity approved for this project. It is intentionally designed without the project name inside the mark so the emblem can work independently as a reusable brand symbol.

> The binary master asset is intentionally not embedded in this PR until the exact selected source image can be committed without transformation or truncation.

The visual system is designed to communicate the project's identity without depending on any one vendor, agent runtime, or enterprise tool.

## Symbol meaning

- **Outer shield** — governance, bounded authority, resilience, and operational trust.
- **Central modular/orchestration core** — composable capabilities, coordinated execution, and the governed control plane.
- **Orbital rings and connected nodes** — swarm-style coordination across specialized skills and operational capabilities.
- **Observability chart** — monitoring, evidence, and operational analytics.
- **Cloud node** — platform and infrastructure integration.
- **Alert node** — incident detection and anomaly intake.
- **Operations gear** — controlled execution and recovery tooling.
- **Verified shield** — policy compliance, independent verification, and trusted recovery.
- **Enterprise skyline** — applicability to real enterprise and smart-environment operations.

The emblem intentionally does **not** use a literal bee as the primary identity. Instead, the `swarm` concept is expressed through distributed nodes, orbital coordination, modular structure, and a protected central control core.

## Recommended usage

Use the primary emblem for:

- repository and project documentation
- presentation title/cover slides
- competition submissions and posters
- website and dashboard branding
- app/social-preview assets derived from the master emblem

## Visual palette

The primary visual language uses:

- deep navy / dark blue for the governed operational core
- electric blue / cyan for connectivity, telemetry, and automation
- gold / amber for authority, orchestration, and premium enterprise identity
- alert orange for incident state
- validation green for verified recovery

## Clear space

Keep clear space around the emblem equal to at least the diameter of one outer functional node. Do not place text, borders, or unrelated UI elements inside this area.

## Background guidance

Preferred usage is on:

- transparent canvas
- dark navy / dark gradient surfaces
- neutral light surfaces with sufficient contrast

Avoid noisy photographic backgrounds or colors that reduce contrast with the blue/gold system.

## Brand consistency

Do not:

- stretch or distort the emblem
- recolor individual functional nodes arbitrarily
- add vendor logos inside the emblem
- add project-name text inside the icon itself
- replace the central orchestration structure with a mascot

The emblem should remain recognizable as a standalone icon so the project can build a consistent visual identity across GitHub, demos, research material, and future commercial deployments.
